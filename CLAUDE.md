# rcfc

Offline-first spaced-repetition PWA with an RWKV scheduler in Wasm. Design: `docs/design.md`.

## Layout

- `src/` PWA client (Vite + vite-plugin-pwa, Dexie, no UI framework)
  - `ui/` DOM helpers and the paper look: `paper.ts` (textures, cut edges, haptics), `checks.ts` (a finished pile's pencil checks, ×N), `light.ts` (tilt light; switched off: study never calls `startTilt`, so the motion sensor is never read), `body.ts` (card physics), `turn.ts` (turning a card over), `picture.ts` (a card's pasted picture), `pencil.ts` (arrow notes, a language word that picks), `ink.ts` (one pencil: draws three dots on the first place a fill is awaited for and rubs them out with its eraser, again and again, then writes each filled place in turn, letter by letter, going on to wait on the next place still coming; a pencil lifting off is taken up by the next writing on the card, `letGo` / `takeUp`, e.g. the picture's note, so it never fades out and back in), `fineprint.ts` (a word's notes as tiny print on the card's answer side; a tap zooms the camera in onto the same text at reading size, scrollable), `sketch.ts` (a picture's place while it draws: the pencil writes the streamed meaning and scene, strikes the scene through and writes it again until the picture comes, a place too small for words (the editor's folded cream side) gets the three dots instead, then the picture is brought in from above the screen and laid down), `launch.ts` (the launch screen: the splash's pile, laid by index.html at the first paint; shuffles after 0.6 s, a pencil note during a model replay; dealt onto the table, turned over into the welcome card, or faded for any other screen; `?splash` overlays the splash to check they match)
  - `domain/` pure logic: event fold, RWKV row derivation, piles (`piles.ts`: deals, draws, sizes), new-card daily limits (`newcards.ts`), stickers (`labels.ts`: names, ids, pile keys), cards (`cards.ts`: duplicates, the draft a card editor holds and the events Add / Save write), a reverse card's blanked example (`gap.ts`), words managed from outside the app (`wordbook.ts`: what the Claude connector's tools do, folded collection in, events out)
  - `engine/` RWKV Web Worker + checkpoints; `EngineApi` is what the app uses (tests stub it)
  - `import/` Import from anything (`anything.ts`: the AI prompt, a permissive reader of pasted tables, the plan and its events; `csv.ts`): pure, text in, events out
  - `store.ts` ties log + engine. No UI side effects: writes return `{ replay }` / set `stale`, the app decides when to reload
  - `session.ts` one sitting at a pile (UI-free; the cards on screen); `sync.ts` sync loop; `pictures.ts` picture queue + offline picture store; `fill.ts` the card editor's fill requests (`app.filler`); `speech.ts` spoken audio: downloaded ahead, offline store, browser voice fallback; `summaries.ts` word notes: downloaded ahead, offline store, the language they're written in
  - `app.ts` shell shared by screens: `app` (store, sync, current screen), `go.*` navigation, `page()` / `fullScreen()`, `setKeys()`
  - `router.ts` `go.*` as browser history, so the phone's back gesture matches the back buttons: Study at the bottom, tabs and study one level up (tabs replace each other), add/import/edit/addLanguage on top of Words (edit also on top of Study); going up = `history.go(-n)`; `back()` (via `app.ts`) is one step back to whatever is under the screen (the card editor leaves with it); a reload shows the screen history was on. `hold(onBack)` (via `app.ts`) pushes an entry for the same screen so back closes a sheet, Select or Edit first; `sheet()` in `app.ts` uses it, and holds are released when a screen renders
  - `screens/` one module per screen; they navigate through `go`, never import each other (except helpers in `languages.ts` and `stickers.ts`). Three tabs: Study (`home.ts`: the table), Words (`words.ts`: every word in one list, rendered in chunks on scroll; chips: languages once there are two or more, stickers on a sideways-scrolling line with + Sticker; with new/learning/known; select → stickers / know / don't know / delete; Edit sticks the open sticker on and off; add/import/edit are sub-pages with a back button; add and edit are the card editor, `card.ts`), Settings (sync + backup only)
  - `main.ts` boot only; `dev/` dev-only URL hooks (`?reset`, `?seed=N`), excluded from production builds
- `rwkv/engine/` Rust RWKV-SRS V1 inference (→ Wasm), checked against upstream goldens in `rwkv/golden/`; `rwkv/models/` weights
- `worker/` Cloudflare Worker: API under `/api/*`; everything else is static assets. `sync.ts` is the sync API, written against a small `SqlDb` slice of D1 so tests run it on bun:sqlite; `pictures.ts` draws and serves card pictures; `fill.ts` fills in a card (LLM, kept in R2); `tts.ts` spoken audio (Azure Speech, kept in R2); `summary.ts` a word's notes (LLM, kept in R2); `oauth.ts` + `mcp.ts` the Claude connector (below)
- `test/` bun tests; `test/support/` harness: fake-indexeddb, `FakeEngine`, in-process sync server (`Device`, `Server`, `Clock`)
- `migrations/` D1 SQL migrations (applied automatically on deploy)
- `scripts/` deploy tooling (below)
- `wrangler.jsonc` the single Worker config: top level = local dev, `env.preview`, `env.production`

## Commands

Bun is the package manager, script runner and test runner (`bun.lock`; never use npm/npx/node). `bun install` to set up. Exception: `bun run dev` runs vite on Node, because the Cloudflare plugin's Miniflare hangs on Bun's incomplete `ws` support; production builds run on Bun (`bun --bun vite build`).

- `bun run build:wasm` builds the engine into `src/rwkv/pkg/` (gitignored; dev/build/deploy run it). Needs `cargo install wasm-bindgen-cli --version 0.2.130 --locked`
- `cd rwkv/engine && cargo test --release` engine goldens + checkpoint round trip; `cargo run --release --example bench` year-of-use benchmark
- `bun run dev` local dev with local D1/R2 (`bun run db:migrate:local` first on a fresh checkout)
- `bun run build` typecheck + build
- `bun scripts/build-icons.ts` redraw the committed app icons (manifest, iOS, favicon) and iOS splash screens (`public/splash/`, light + dark per iPhone screen; it rewrites their `<link>` block in `index.html`) from `scripts/icons/icon.html` (cut paper on a canvas: a pile, RCFC on the top card; the splash is a big pile on the table) in headless Chromium, after changing the drawing
- `bun test` all tests (`bun:test`): pure domain, Store/StudySession on fake-indexeddb + fake engine, multi-device sync through the real Worker handler.
- `bun run smoke [url]` UI smoke test in headless Chromium (Chromium.app, else Chrome; `RCFC_CHROMIUM` overrides) over the DevTools Protocol, no deps: starts a dev server on :5199 unless given one, walks language → add → table → study → its finish → finished spot → the same cards again → words → settings/sync → seeded replay with the real model → select/know/delete → a second language (Add picker, Words chips, a second pile) → a Spanish word translated into Russian (same pile) → Import from anything (copy prompt, paste a reply, preview, add, paste again adds nothing, a raw Duocards file picked), fails on page errors; screenshot on failure in `.wrangler/smoke/`. `RCFC_HEADFUL=1` to watch, `RCFC_TRACE=1` to log clicks, `RCFC_SHOTS=1` to save screenshots of the add/study/table screens. Against preview it runs up to the seeded replay (that and later steps need the dev-only hooks), drawing real pictures (~60 neurons each); the install banner is snoozed so it doesn't cover the tab bar. ~4 s after the dev server is up
- Dev URL hooks (dev server only): `/?reset` wipes this origin's data, `/?seed=60` adds a demo deck with a month of reviews. `.dev.vars` (gitignored) `DEV_PICTURE_DELAY_MS` / `DEV_FILL_DELAY_MS` slow the local placeholder picture / fill (default 900 ms) to watch the pencil; restart the dev server after changing it
- `bun scripts/check-connector.ts <url> [--write]` the Claude connector over HTTP: discovery always; `--write` (dev, preview) also a throwaway account through sign-in, tokens, tool calls and the app's pull. Part of `check-deploy.sh` (production: discovery only)
- `bun run deploy:preview` build → remote D1 migrations → deploy → smoke test; prints the URL
- `bun run deploy:prod` same for production; refuses a dirty tree. **Only on explicit user request.**
- `bun run check:deploy preview|production|<url>` re-run the smoke test
- `bun run cf wrangler <cmd>` any wrangler command with credentials loaded
- `bun run cf:bootstrap` one-time (idempotent): creates D1 + R2 for preview/prod, writes D1 ids into `wrangler.jsonc`

Last deployed URLs are saved in `.wrangler/url-preview` and `.wrangler/url-production`.

## Credentials

`scripts/cf.sh` supports two modes:
- **OAuth** (current): the user ran `bunx wrangler login`; wrangler stores and refreshes the token in `~/Library/Preferences/.wrangler/`. It lapses after long idle periods.
- **API token**: `~/.config/rcfc/cloudflare.env` (mode 600) with `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`; takes precedence when present.

Never print, copy or commit credentials. If cf.sh reports "not authenticated", ask the user to run `bunx wrangler login` in their terminal (it needs a browser; you can't do it).

## Domain notes

- Entity ids are random positive integers < 2^53 (`src/domain/ids.ts`), not full 64-bit: fit rwkv-srs `i64`, exact in JS, JSON-safe.
- The importer is pure (text in, events out) and dedups on normalized word + translation + pair, so pasting twice is safe. A word already there is merged (`mergeOf`): it gets the row's stickers it doesn't wear and the example / notes it lacks, never anything written over, progress untouched (app import and the connector's `add_words` alike). Imported notes must not auto-queue enrichment at import time (pictures are queued when a word comes up: among a pile's next cards, or shown in study).

## UX notes

- Look: everything is cut from paper (`src/style.css` header). Sage table, white card stock, coloured paper buttons/tabs with hand-cut edges (`--cut-1..4`), Balsamiq Sans (self-hosted via `@fontsource`, precached; has Cyrillic). Textures are canvas bitmaps made at boot (`src/ui/paper.ts`), never SVG filters. Anything that moves per frame changes only transform/translate/opacity; tilt light writes `translate` on `[data-light]` elements (`src/ui/light.ts`), never a custom property on a screen root.
- Piles (`src/domain/piles.ts`, design: docs/design.md "Piles, labels and languages"): every study day a language's pile is dealt its size (`pile_dealt`; 20 to start, +5 after "more" that day however many times, -5 when left unfinished, 10..50; "more" deals `MORE` = 10). The pile fixes how many, not which: a card is chosen when drawn (due weakest first, then new words within the daily limit), except seen ones (top and peeked card per device, Again'd cards wait under the pile, past the rollover too). Got it/Easy = done for the day in every pile (the model's minute-scale predictions are noise). A face is not drawn within an hour of its twin. Reviews record their `pile`.
- The table (`src/screens/home.ts`): a spot printed on the table per language, then per sticker, two per row, then always New pile (names a sticker, then Words opens on it in Edit), with its pile: thickness = cards left (1.5 px each, up to 30 edges), the top card face up, edge colours from `StudySession.faces` (the same fixed colours study shows). The table deals nothing (`StudySession.settle`; an undealt pile draws as if dealt); study deals. It draws at once from the last predictions (waits only at launch, when there are none), then refreshes all piles' predictions in one engine call and redraws only the spots that changed. A finished pile's spot keeps its checks (`src/ui/checks.ts`: the day's, a blue one once more was dealt and finished, ×N from the second; `DayDeal.rounds`); tapping a finished spot opens that pile's finish in study (no sheet).
- Opening a pile from the table waits for nothing (`StudySession.startNow`: the table's predictions and fixed top card, fresh predictions in the background; only without predictions, e.g. a reload into study, does it wait with "Preparing…"); the tapped pile (a copy, `app.opening`) leaves through the top of the screen and the study pile is brought in along the path the editor lays a picture down (`Table.dropIn`, `sketch.ts` bringIn), only moved and turned: scaling it or blurred shadows lagged on Android and shimmered the cards under the top one when the scaling ended; never one grown into the other (growing one into the other dropped frames on Android and showed their faces differ).
- Study (`src/screens/study.ts`): a finished pile ends in study (`Table.finish`): its check drawn with paper bits, "Done for today" / "Bonus done", "Back to the table" as the big button, today's cards (`StudySession.crossed`) moved from under the pile into the room below the title ("tap for today's N again": they stand up into the pile, `StudySession.againThese`, kept per device and pile with the cards on screen, for that day), and handfuls of words not done today lying aside: "+10" while there is more (`StudySession.moreCount`), and on a sticker with more left than that a thick "all N left" (`restCount`, `StudySession.rest`; with ≤10 left the one handful says "all N left"); no Add words (done is done). Opened from a finished spot it shows the same, the check already drawn ("Nothing due" when nothing was studied); tapped, it is dealt onto the table there and studying goes on (design: docs/design.md "The table (Study tab)"). A real pile (each card has a fixed pose; its height is the cards left; the one under the top card shows `StudySession.peek()`, fixed once shown; deeper cards show only their colour, white or cream side up, fixed once their edge shows: the card drawn into that spot must lie that side up unless none is left), tap, Show answer or a sideways drag turns the card over (the drag turns it up to its edge, never past, so the answer stays hidden until let go; `src/ui/turn.ts`), then drag right = Got it (3), left = Again (1, tucked under the pile), up = Easy (4); arrow keys too. Got it / Easy: the card flies off, then comes back in from that side turned crosswise, shrunk to the screen's width, and slides under the pile, its ends showing on both sides (`src/ui/crossed.ts`, WAAPI transform only; the table's spots show them too, `home.ts` `crossed`). Once turned, a tap or Space turns it over again (onwards the same way) to look at the other side; the ratings stay. A pencil in the corner of a turned card opens the card editor; back returns to the same card still turned (`StudySession.keepTurned` / `takeTurned`, the time looked at before kept so editing isn't counted). Pencil notes on the back teach the throws and retire per direction after 3 throws (localStorage `rcfc:throws`). Android haptics (`navigator.vibrate`) incl. a detent tick when a release would answer; iPhone has none and can't: iOS 26 taps only when a finger taps a real switch checkbox, never one clicked from code, and never during a drag (tried on the phone).
- Stickers (`src/domain/labels.ts`, `src/screens/stickers.ts`; design: docs/design.md "Labels"): labels on words, many to many, across languages, never fed to the model. Events `label_created` (id derived from the name when new, so offline devices agree; a used id is never reused), `label_renamed`, `label_deleted`, `notes_labeled`; they stay until deleted, even empty (Words shows "No words yet." with a pencil arrow to Edit; the table an empty spot). Pile `label:<id>`: due weakest first, then its new words, not held back by the daily limit (the pile size caps them) but counted toward their language's; after "10 more" or "all N left" that day it goes wide (every word once, due or not, done-today last, new words free and not counted: `notCounted`). "All N" (`pile_dealt.all`) doesn't grow the next deal. A word on top of one pile isn't drawn on top of another unless it's all that's left (`avoid`); a card answered Again belongs to its pile (`skip` elsewhere). Colours: `LABEL_COLORS` (CSS `--st-<name>` and `--st-<name>-on`); a new sticker gets the least-used one (`freshColor`, carried on `label_created`), `label_colored` changes it from the pencil sheet's swatches; `paint()` (`stickers.ts`) sets `--sticker`/`--sticker-on` and `data-label` on anything drawn in a sticker's colour, so a change repaints it at once.
- Card editor (`src/screens/card.ts`, design: docs/design.md "The card editor"): Add and Edit are one screen that looks like the card, both sides (stacked; side by side from 900 px). Pencil arrow notes point at empty places, the languages are words in them (pickers on Add, plain on Edit). Its bar is sticky and holds Add (new card; Enter on the later places adds too) or the bin (saved card), nothing at the bottom (the keyboard covers it). A draft (`CardDraft`) until Add, which appends `addEvents` (`src/domain/cards.ts`); leaving a typed card not added (back button, gesture via a `hold`, a tab via `guardLeaving`) asks on a sheet (`sheetOr`: back again throws it away). Edit saves `saveEvents` when left, with an Undo slip (`slip` in `ui/h.ts`, `undoEvents`); the bin deletes at once, Undo writes `note_restored` (the later of delete / restore wins). With the keyboard open and no room for the whole card (`src/ui/fold.ts`, visualViewport), the side typed on stays open and the other is tucked under it, its main line showing; a tap or Enter swaps them (translate only). The picture draws on the card 1.5 s after typing pauses (or Enter / blur) through `pictures.sketcher()` (outside the queue, older results stale); Add takes it, or `pictures.adopt` attaches one still drawing (the queue only if it fails). Exact repeat refused; same word + pair with another translation gets a pencil note. Own notes `memo_target` / `memo_known`, one per side, shown in pencil in study. After Add: a fresh card and the cards added this sitting. A card opened from the editor (the duplicate note's link, an added row) opens over it (`openOver`: the screen's nodes are kept, `keepHoldsNext` keeps its gesture hold under the new one's) and leaving puts the draft back untouched.
- Launch (`src/ui/launch.ts`): the iOS splash and the app's launch screen show the same pile in the same place: geometry in `src/ui/launch.json`, card pictures in `public/launch/` (drawn by `scripts/build-icons.ts`, which also writes the launch block into `index.html` and fails if the launch screen is more than 2 device px off any splash). Nothing waits for it: the first screen shown sends it off (`show()` / `fullScreen()` for other screens, `home()` for the table and the welcome card). Its pile never moves at the first paint (the slide transition is on only while shuffling).
- Cards are physical: one card per word, the studied language on the white side (word, speak button, example), the known language and the picture on the cream side (`--card-known`). A forward card lies white side up, a reverse card cream side up; a reverse card's cream side also shows the example with the word blanked out (`src/domain/gap.ts`, found in code by letters: every form starting the same, else no sentence), so examples must hold the word and leave only it fitting (connector instructions, import prompt). No language label on the card.
- Fewer buttons, no study settings. New words a day are per studied language. No decks or pairs in the UI: the UI shows only the studied language ("Spanish"), which exists while it has words (`languages.ts`) and has one pile (`lang:es`), whatever its words' translations are in. Each word keeps both languages (`note.lang_pair`; `to` = its translation's language, for the cream side's `lang`, and later for filling translations and explanations), picked per card in the card editor's pencil note and defaulting to the last pick for that studied language (localStorage). Words shows every word; with two or more languages, chips narrow it to one (per device). Add adds to the last language used, switchable by the language word in the pencil note (a native picker whose last option, "Add a language…", opens a sheet); nothing is made until its first word. Pile keys from when piles were per pair (`lang:es>en`) are read as `lang:es` in the fold (`pileKey`). Underneath, one hidden deck per studied language stays, because the model takes a deck id: `deckFor` reuses one (lowest id), else makes one whose id is derived from the language (`derivedEntityId`), so two devices adding the same new language offline make the same deck.
- Target recall is fixed (`TARGET_RECALL` 0.9 in `src/domain/scheduler.ts`; presets' `desired_retention` is ignored). Day rollover (4) and new words per day (10) stay in the preset but have no UI; "more" on an empty pile raises today's new-word limit by what it deals.
- Import from anything (`src/screens/import.ts`, design: docs/design.md "Import from anything"): copy a prompt for the user's AI chat, paste its answer or pick a file, preview, add. Exports go through the AI, except a raw Duocards export, which reads directly (its studied language from the file name, `fileLang`); the reader quietly takes much more than the prompt asks for (other headers, separators, markdown tables, language names, progress words, dates). The prompt's reply-language rule and its localized last line must stay at the end (tested: higher up, non-English users got English). Status: known = both faces Easy once, learning = prioritized, new.
- Selected words: "I know" (`Store.markKnown`) answers Easy on both faces of the word, seen or not (an unseen face left behind was drawn as a new card, first in the queue and uncounted, so known words filled the piles; `Store.repairKnown` answers the unseen face of such words once per device, after a sync went through and not during study (`main.ts`): Easy-only words with a review outside any pile). The daily new-word limit leaves out only cards marked known (first answer Easy with no `pile`); a new card answered Easy in study counts; "Don't know" (`Store.markUnknown`) answers Again on studied cards and queues unseen words to be learned next (`notes_prioritized` event, latest request first).
- The list status (`wordStatus`) is new / learning / known: known = every studied card last answered Easy, or ≥ target recall a week ahead. Never show P(recall) now as progress: it is ~100% right after any answer and dips minutes later.

## Picture notes

- Pipeline (`src/domain/pictures.ts`): Gemma 4 26B A4B (`SCENE_MODEL`, thinking off; Granite 4.0 micro before it drew the wrong meaning of 4 in 26 two-meaning words, e.g. a bench for banco = bank) writes one scene, FLUX.2 klein 4B draws it at 768×512 in the house cut-paper style (medium first in the prompt, or it drifts to photos). The meaning is chosen first (user's choice, else the only listed meaning, else a separate LLM call picks one of the listed meanings from the example, else the first); the scene is written from word + meaning only, never the example (given one, the LLM drew the sentence's situation instead of the word).
- Kind of picture (`parsePlan`): the scene LLM answers `kind` first: `scene`; `digits` for numbers, times and years (drawn as cut-paper numerals by `digitsPrompt`: FLUX miscounted "thirteen apples"; digits read the same in every language, so they give nothing away; ordinals get the bare digit, since "3." came out "33."; single digits need their own wording or "7" becomes "7777"); `none` for words no picture can show (of, however, they): the stream answers `{none, sense}`, the drawing's neurons are refunded, and the client records it as removed (`r2_key: null`), so it's never queued again. "draw one anyway" / "draw one" / details send `always`, which takes `none` off the menu. Local dev answers none for but/of/the/however/although.
- Checked after the model answers (`planProblem`, worker `checked`): digits for a time unit / ordinal / dozen, or a scene naming a banned prop (`BANNED`: lightbulb, calendar, sign, crowd, mirror…; fine when the meaning names it) asks once more (`retryMessages`, ~8% of words); broken again = none. Modal and aspect verbs (`NO_PICTURE`) and groups of people by religion, ethnicity, orientation or identity, and ideologies (`GROUPS`: a costume for a people is a stereotype) are none in code (English meanings). Who a scene shows is picked per word in code (`womanOrMan`, a hash: asked in the prompt alone, every doctor was a man), unless the word's own gender says; political words are drawn plainly, insults literally, countries as a landmark. The prompt and these lists came from a focus group over 1,122 frequent words in 6 languages (round 1 76% fine → round 3 92%); the harness is a throwaway script, re-run it on OpenRouter (`google/gemma-4-26b-a4b-it`, key in `~/.config/rcfc/openrouter.key`) before big prompt changes.
- No writing in pictures: the picture is on the known side, so a drawn word gives the answer away. The scene LLM ignores the rule and writes quotes and dialogue, so `withoutQuotes` strips them in code. The style asks for one free-standing cut-out with an irregular hand-cut outline on white, not a full-frame panel.
- Streamed: the client asks `stream: true` and gets NDJSON lines (`PictureLine`: `{sense}`, `{scene}` = all of it so far, then `{key,sense,scene}`, `{none,sense}` or `{error}`); the scene LLM streams without `json_object`, `sceneSoFar` reads the partial JSON and stops before any quote mark (quotes are stripped from the final scene). `SketchRequest.onText` (editor) and `Pictures.text(noteId)` (queue, for study's `livePicture`) carry it to `SketchNote`, which in the editor yields to the fill pencil (`Ink.busy()`): one pencil on the card. The editor shows pictures on their paper (`cutout(key, tilt, paper)`). Local dev streams the placeholder with a 0.9 s draw.
- Comparing scene models on preview: `POST /api/pictures` with `scene_only: true` (and `scene_model`) answers `{sense, kind, scene | digits}` without drawing; refused on production.
- Cost: the free 10,000 neurons/day (UTC, per account) plus up to ~$0.5/day over it is fine (user, Nov 2026): production caps at 50,000, preview and dev at 9,000. The Worker reserves ~60 neurons per picture in D1 `ai_budget` and answers 429 past `PICTURE_NEURONS_PER_DAY`; the client queue waits for the reset. Error 3030 (false safety flag) is retried with new seeds.
- When: on the card editor while typing (see UX notes), and at once when a card without one is opened in it (an imported word: its own sketcher, `pictures.adopt` makes it the card's however the editor is left, back gesture included; failing, the queue draws it); any other word when it comes up: the next `AHEAD` (10) cards of each pile (`StudySession.upcoming`), queued from the table and after each card in study, drawn after pictures needed now (`PicJob.ahead`), so they are there when the card shows, offline too; and the card on top if still missing. Redraws from the card editor with details (the pencil on the picture's corner). A removed picture (`asset_attached` with `r2_key: null`) is never redrawn automatically.
- Client (`src/pictures.ts`): jobs in Dexie `pic_jobs` (per device, not synced; the result syncs as `asset_attached`), downloaded pictures get their photographed paper flattened to pure white (`src/domain/paper.ts`, so light cards show through with multiply blending; dark mode pastes them as a light cut-out), are re-encoded and kept in `pic_blobs` for offline study. Local dev has no AI binding: the Worker draws an SVG placeholder for free.

## Fill notes

- The card editor fills in what wasn't typed at a typing pause (0.7 s; the picture waits 1.5 s) (`src/domain/fill.ts`: prompt, parsing, and the editor rules `fillAsk` / `applyOption` / `clearAuto`): word typed → translation + example + other meanings ("or:", a tap swaps); translation typed → the word (article where nouns take one) + example; both → example. "did you mean X?" offers the dictionary form / spelling / article; never applied without a tap. Fills never write over typed text (`auto` = places a fill wrote, untouched since). A translation typed in other letters switches its side's language (`src/domain/script.ts`, script only); picking a side's language translates it: the other side's word becomes the source, this side is rubbed out and filled again (switching the translation's keeps the example: `applyOption` `keep`); with the other side empty it is only relabelled. The picture waits for a fill that may change the words. Add/Save wait for one on its way (≤ 8 s). The pencil (`src/ui/ink.ts`) only animates: the input holds the whole text at once, a layer over it shows the letters; no layout shift when a fill lands (notes share the arrow note's line, empty notes keep their room).
- `POST /api/fill` (`worker/fill.ts`): Gemma 4 26B A4B (`FILL_MODEL`, thinking off). The editor asks `stream: true`: NDJSON `FillLine`s, `{first}` = the first option's places as they are written out (`firstSoFar`; options come before `suggest` in the reply, so the translation lands ~0.9 s in, the whole fill ~1.7 s), then `{fill}`; streamed without a JSON mode (with one the reply comes whole), a reply that doesn't parse is asked again with json_schema. The pencil writes the first option and the picture starts drawing from `{first}`. Preview-only `timing: true` times a model's streamed reply (first piece, translation, end) for comparing models (Nov 2026: Gemma ~1.1 s to the translation; Llama 3.3 70B / Sea-Lion ~0.6 s but wrong word forms; Mistral Small 3.1 ~1.0 s), ~15 neurons from the pictures' `ai_budget`; replies kept in R2 `fill/<sha256>.json` keyed by `FILL_VERSION` + model + pair + text: bump `FILL_VERSION` when the prompt changes. Outside production a request may pass `model` to compare models. Local dev (no AI): `devFill` placeholders ("banco (en)"), answered after 0.9 s like a real fill.

## Word notes

- `src/domain/summary.ts` (prompt, parsing, keys) → `POST /api/summary {from,to,in,word,translation}` (`worker/summary.ts`): DeepSeek V4.1 Flash (`SUMMARY_MODEL`, thinking off, json_schema), ~100 neurons from the pictures' `ai_budget`, kept in R2 `summary/<sha256>.json` keyed by `SUMMARY_VERSION` + model + pair + `in` + words: bump `SUMMARY_VERSION` when the prompt changes. Outside production a request may pass `model`. Local dev: `devSummary` placeholders.
- Client (`src/summaries.ts`): not events. Downloaded with the pictures' `AHEAD` cards (Dexie `sum_blobs`, per device), else asked for when the card shows; 429 pauses until the reset. Written in the studied language unless switched on the zoomed page (localStorage `rcfc:notes-in:<from>`).
- Study (`src/ui/fineprint.ts`): tiny print (the page scaled by `K`) on the answer side; the zoom moves a copy of the card (`.sum-stand`, transform only), never `.study`: scaling the screen's ~30 layers 6.25x left Android Chrome with missing tiles and flashes; and the real page (`.sum-view`) rides on it from the tap (its transform = the copy's, then the inverse of where the copy ends), fading in during the zoom and untransformed when it lands: nothing is swapped at the end (a swap showed a white frame and a shifted grain).

## Speech notes

- Voices (`src/domain/tts.ts`): one Azure neural voice per language in `LANGS`, 10% slower. `GET /api/tts?lang=&text=` (`worker/tts.ts`, header `X-User-Code`) serves R2 `tts/<voice>/<sha256>.mp3`, else makes it once with Azure Speech (secret `AZURE_SPEECH_KEY`, var `AZURE_SPEECH_REGION`) and keeps it. Characters sent to Azure are capped per UTC month in D1 `tts_budget` (`TTS_CHARS_PER_MONTH` 100k: the key is AccentBuddy's free F0 resource, `francecentral`, whose 500k a month both apps share); past it 429. No key (local dev): 404 "no voice service", and the app uses the browser voice.
- Client (`src/speech.ts`): word + example of the cards coming up are downloaded with the pictures' `AHEAD` (Dexie `tts_blobs`, per device, not synced) and played with Web Audio (unlocked on the first tap; `navigator.audioSession` "playback" so iOS's silent switch doesn't mute it). Not on the device: fetched for up to 1.5 s, else the browser voice (`src/ui/speech.ts`). A forward card says its word when it comes up; a reverse one when turned to the word side; the example has its own speak button. A scrap of card stock on the Study tab's title line and in study's top corner (`src/ui/autoread.ts`: pencil speaker, turned over "shh") only switches that reading by itself on or off (`Speech.auto`, localStorage `rcfc:autoread`; for studying while other audio plays, e.g. music for a baby); switched off, iOS sound plays along with other apps' audio (`audioSession` "ambient", muted by the silent switch) instead of "playback" (through the silent switch, but it pauses other apps' music). `rcfc-said` window events tell the smoke test what was said.
- Health (`/api/health`) says whether the key is set.

## Sync notes

- The sync code (16 base32 chars, `src/domain/sync.ts`) is the account: no sign-in, whoever has it reads and writes that user's events. Every device gets one on first launch, so sync (and the server copy, which is the cloud backup) is always on. Pairing = `#k=<code>` link or QR in Settings, or typing the code; joining pushes this device's events to that account and pulls everything.
- Worker: `POST /api/sync/push` (≤500 events, `INSERT OR IGNORE`), `GET /api/sync/pull?after=<seq>` (pages of 500), header `X-User-Code`. The server never reads payloads.
- Client (`src/sync.ts`): push cursor = local Dexie seq; pulled events are stored with `remote: 1` and never pushed back. Pulled reviews that sort after everything processed feed RWKV incrementally; an older one (or a rollover change of a used preset) sets `store.stale` and the app reloads at the next safe moment (home screen) for a full replay.
- Several presets can exist after pairing (each device makes a default): `defaultPreset()` picks deterministically (lowest id among presets decks use).

## RWKV notes

- Review events store raw facts; `src/domain/rows.ts` derives RWKV inputs (day_offset from first review day, elapsed, state) following RWKV4Anki `review_rows.py`. Changing that derivation: bump `ROWS_VERSION` (forces a full replay).
- Engine checkpoint lives in IndexedDB `rcfc-engine`, keyed by model sha + rows config; on mismatch the app replays the log.
- Known scale limit: all recurrent state is held in memory (~70 KB/card, ~0.5 GB after a year of daily use). Fine for months; needs on-disk/evicted states before then.

## Claude connector notes

- Design: docs/design.md "Claude connector". `https://<app>/mcp`, remote MCP (Streamable HTTP, stateless `createMcpHandler` from `@modelcontextprotocol/server`, no `agents` package); Settings shows the address. Tools in `worker/mcp.ts`, each a fold of the user's D1 events (`loadEvents`) → `Wordbook` (`src/domain/wordbook.ts`) → `appendEvents`, device `claude`, `monotonicClock` so two writes to one field in a call keep their order. The events are the app's own (Add/Save/bin/stickers/I know/Don't know, importer dedup), so the app needs no change to see them. Status has no model there: prediction-known words read as learning.
- OAuth (`worker/oauth.ts`): `@cloudflare/workers-oauth-provider` as authorization server + resource server in this Worker, issuer = `PUBLIC_ORIGIN` (preview/prod vars; dev: the request origin); another host answers 421. Scope `words`; refresh tokens 90 days past last use. The approval page `/oauth/authorize` is ours: it reads this browser's sync code from the app's IndexedDB (same origin), else takes the pasted pairing link; `/oauth/check` gives a code's word count; an unknown code is refused before the consent handle is used. Token props = `{ code }`; grant user id = a hash of it.
- Paths reach the Worker via `run_worker_first` (`/mcp`, `/oauth/*`, `/.well-known/oauth-*`) and are in the service worker's `navigateFallbackDenylist`. Compatibility flag `global_fetch_strictly_public` is for the library's client-metadata fetches.
- Tests: `test/wordbook.test.ts`, `test/connector.test.ts` (whole flow on bun; `cloudflare:workers` mocked, `test/support/kv.ts` fake KV, `test/support/workers.d.ts` stands in for Workers globals in the app's typecheck).
